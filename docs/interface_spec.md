## 2. 板卡与器件（已冻结 v1.1）

| 项目 | 选型 | 理由 |
| --- | --- | --- |
| 器件系列 | **Xilinx Artix-7** | 团队确认（2026-10-11）。无 PS，全部功能（摄像头配置、手势、游戏、显示）由 PL 承担，最能体现 FPGA 核心价值 |
| 首选型号 | **XC7A100T-1CSG324C**（如 Nexys A7 / Arty A7-100T） | 100T 的 LUT/BRAM/DSP 足以承载 640×480 视频流水线 + 游戏核心 + 并行碰撞，并留裕量做 ILA 调试 |
| 备选型号 | XC7A35T（如 Basys 3） | 若已有该板；代价是资源偏紧，需把视觉处理降到 320×240 并精简缓冲 |
| 封装 / 速度 | CSG324 / -1（-2 亦可） | -1 足够 100 MHz；-2 若采购方便 |
| 具体开发板 | 采购时确认（候选：Nexys A7、Arty A7-100T、Basys 3） | 只需满足下方冻结判据，器件系列不受影响 |

**冻结判据（按 Artix-7 定稿）**

1. **时钟**：板载晶振常见 100 MHz；若为 50 MHz，经 MMCM 倍频到 100 MHz。第 3 节已按 100 MHz 主时钟设计，不受影响。
2. **摄像头**：DVP 并口必须由 PL 直接采集（Pmod 接 OV7670 / OV5640 DVP 模组；SCCB/I2C 由 PL 主机完成）。
3. **显示**：VGA（Nexys A7 / Basys 3 板载 VGA；Arty 无板载 VGA，需 Pmod VGA）。选定具体板后补齐 VGA 引脚到 XDC。
4. **资源**：XC7A100T 满足；若用 XC7A35T，需在第 2 周先做一次资源预评估确认可行性。

**选 Artix-7 带来的架构调整（重要）**

| 原方案（Zynq） | 现方案（Artix-7，已定） |
| --- | --- |
| PS 负责摄像头初始化 / 日志 | **PL I2C 主机**完成 SCCB 配置；**PL UART**输出日志 |
| PS 加载 Overlay | 无需；纯 RTL 工程，比特流经外部 SPI/QSPI Flash 或 JTAG 配置 |
| PS 跑性能统计 | **PL 计数器 + UART 回读**（或 ILA）统计帧率/延迟 |
| DDR 可用于全帧缓冲 | 无 DDR（或板载 DDR 由 MIG 驱动，作为可选）；**默认行缓冲 + 双缓冲** |

> **风险提示**：USB 摄像头方案会削弱 FPGA 实时处理的核心价值，且难以在 PL 侧做流水线采集，**本项目不采用 USB 摄像头**。
## 3. 时钟标准（冻结）

| 时钟名 | 频率 | 来源 | 用途 | 容差 |
| --- | --- | --- | --- | --- |
| `clk_sys` | **100 MHz** | 板载晶振经 MMCM 倍频 | PL 逻辑主时钟、AXI4-Lite、游戏核心、视觉后处理 | 必须锁相稳定，抖动 < 100 ps |
| `clk_pix` | **25.2 MHz**（VGA 理想值 25.175 MHz） | MMCM 从 `clk_sys` 生成 | 摄像头像素时钟域 / VGA 像素域 | ±0.5% 内均满足 640×480@60 |
| `pclk_cam` | 由摄像头输出（24–25.2 MHz） | 摄像头（DVP 模式） | 采集写入 FIFO 的写侧 | 与 `clk_pix` **同一 MMCM 域或异步 FIFO 隔离** |
| `tick_60hz` | **60 Hz**（使能脉冲，非独立时钟） | `clk_sys` 分频计数 | 游戏逻辑步进 | 1 666 667 个 `clk_sys` 周期/拍 |
| `tick_frame` | 30 Hz（使能脉冲） | `clk_sys` 分频计数 | 手势特征更新、去抖计数 | 依据实际摄像头帧率标定 |

**硬性规则**

1. **只允许一个 MMCM/PLL**，所有衍生时钟都从它出，便于时序约束与调试。
2. 除 `clk_sys` 与 `clk_pix` 外，**一律使用使能脉冲分频（clock enable），绝不生成新的门控时钟**。
3. `clk_pix` 与 `clk_sys` 之间**只允许通过异步 FIFO 或双触发器同步器**通信。
4. 所有时钟必须在 XDC 中显式 `create_clock`；`clk_pix` 若由 MMCM 生成则
   用 `create_generated_clock` 声明，禁止留空。
5. 跨域路径必须用 `set_false_path` 或 `set_max_delay -datapath_only` 约束并注明理由。

### 3.1 复位标准（冻结）

| 项目 | 结论 |
| --- | --- |
| 极性 | **低电平有效**，命名一律 `rst_n` |
| 类型 | 异步置位、同步释放（`async assert / sync de-assert`） |
| 实现 | 每个时钟域一个"复位同步器"模块，2 级触发器打拍后扇出 |
| 复位源 | 全局：板载按键；局部：`game_core` 的软件复位位（AXI4-Lite 寄存器） |
| 禁止 | 禁止直接用按键信号扇出到全设计；禁止对复位做反相或与非组合逻辑 |
| 上电行为 | 复位后所有模块处于 IDLE，视觉流水线前 10 帧为热身期并丢弃输出 |

## 4. 外部接口标准（冻结）

### 4.1 摄像头输入

| 项目 | 结论 |
| --- | --- |
| 首选接口 | **DVP 8-bit 并行**（如 OV5640 / OV7670 模组） |
| 信号 | `pclk`、`vsync`、`href`、`data[7:0]` |
| 配置总线 | **SCCB（兼容 I2C）**，100 kHz 或 400 kHz，由 PL 的 I2C 主机实现 |
| 分辨率 / 帧率 | **640×480 @ 30 fps**（RGB565 或 RAW8） |
| 备选接口 | HDMI 输入（需 TMDS 接收器或官方 XAPP 方案） |
| 明确排除 | USB（UVC）摄像头 |

### 4.2 显示输出

| 项目 | 结论 |
| --- | --- |
| 首选接口 | **VGA**：`R[3:0]`、`G[3:0]`、`B[3:0]`、`hsync`、`vsync`，4-4-4 bit R-2R 电阻网络 DAC |
| 时序 | **640×480 @ 60 Hz**，像素时钟 25.175 MHz，行 800 总像素 / 场 525 总行 |
| 同步极性 | `hsync` 负极性、`vsync` 负极性（VGA 标准） |
| 有效区 | `x: 0..639`、`y: 0..479`（局部坐标，从 `hsync`/`vsync` 后消隐期结束算起） |
| 备选接口 | HDMI 输出（TMDS，720p 或 640×480 倍频） |
| 排除方案 | 依赖 PS 侧显示器驱动的方案（会削弱 PL 显示控制价值） |

### 4.3 调试接口

| 项目 | 结论 |
| --- | --- |
| 在线调试 | **ILA** 抓取 `cmd_valid`、`cmd[3:0]`、`feat_*`、玩家坐标、碰撞标志 |
| 状态指示 | 板载 LED：`led[0]` 心跳（1 Hz）、`led[1]` 帧有效、`led[2]` 手势有效、`led[3]` 游戏运行 |
| 串口日志 | UART 115200 8N1（经 PS 或 PL UART），输出帧率与延迟统计 |
| 抓图 | 视觉中间结果经 ILA/BMP 导出，与 Python golden model 逐帧比对 |

## 5. 内部接口标准（冻结）

### 5.1 视频流总线：AXI4-Stream

| 项目 | 结论 |
| --- | --- |
| 协议 | AXI4-Stream Video（Xilinx 约定） |
| `TDATA` 宽度 | **32 bit** |
| 像素打包 | 8-bit 灰度时每 beat 携带 **1 像素**（低 8 位有效，高 24 位补零）；若做 RGB 直通则每 beat 2 像素 RGB565 |
| `TUSER` | bit0 = **SOF**（帧首像素） |
| `TLAST` | 行尾（EOL）置 1 |
| `TVALID`/`TREADY` | 标准握手，**两端都必须支持背压**，禁止假设 `TREADY` 恒 1 |
| 时钟 | `s_axis_aclk = clk_pix`（采集域）；跨域经异步 FIFO 到 `clk_sys` |

### 5.2 控制总线：AXI4-Lite

| 项目 | 结论 |
| --- | --- |
| 时钟 | `s_axi_aclk = clk_sys = 100 MHz` |
| 位宽 | 32 bit 数据 / 12 bit 地址 |
| 从机数量 | 视觉配置（B）、游戏配置与状态（C）、系统控制（A），建议合并为 1 个 AXI4-Lite 互联 |
| 写语义 | 只写寄存器立即生效；只读寄存器反映当前状态 |
| 软复位 | `0x00[0]` 软复位；`0x00[1]` 启动/暂停 |

### 5.4 时钟域交叉（CDC）规则

| 路径 | 方法 | 参数 |
| --- | --- | --- |
| 视频流 `clk_pix` -> `clk_sys` | **Xilinx 异步 FIFO（FWFT）** | 宽度 36 bit（32 数据 + SOF + EOL），深度 512 |
| `cmd_valid`/`cmd[3:0]` -> 游戏域 | 双触发器同步 + `valid` 脉冲展宽至 >= 4 个目标时钟周期 | 独热编码保证多比特安全 |
| `feat_*` -> `clk_sys` | 帧末**信箱（mailbox）**寄存器组 + `feat_valid` 单比特同步 | 多比特数据用"数据稳定 + 单比特有效"方式跨域 |
| 计数器/状态回读 -> AXI | 双触发器同步 | 仅用于显示与日志，不参与控制 |

**禁止**：多比特二进制计数器直接跨域、用组合逻辑产生跨域使能、跨域路径缺失 XDC 约束。

## 6. 分辨率与坐标标准（冻结）

| 层级 | 分辨率 | 说明 |
| --- | --- | --- |
| 采集 | **640×480** | 摄像头原始输出 |
| 视觉处理 | **320×240**（2×2 降采样） | 帧差 / 肤色分割 / 形态学 / 质心统计 |
| 手势特征 | 640×480（换算回原坐标） | 便于阈值表与文档统一；见 `docs/gesture_spec.md` 第 1 节 |
| 游戏内部 | **320×240** 虚拟坐标 | 玩家 / 子弹 / 敌机位置均以此为准 |
| 显示 | **640×480@60** | 游戏画面上采样 2× 输出 |

**坐标宽度约定**

| 量 | 位宽 | 范围 |
| --- | --- | --- |
| 采集像素坐标 `x` | 10 bit | 0..639 |
| 采集像素坐标 `y` | 9 bit | 0..479 |
| 游戏坐标 `gx` | 9 bit | 0..319 |
| 游戏坐标 `gy` | 8 bit | 0..239 |

**阈值缩放规则**：`gesture_spec.md` 中的像素阈值以 640 宽为准。
若视觉处理降到 320 宽，则 `cx`、`w` 阈值除以 2，`area` 阈值除以 4，`open` 不变。

## 7. 延迟与性能预算（冻结）

| 指标 | 目标值 | 测量方法 |
| --- | --- | --- |
| 摄像头帧 -> 手势命令 | <= 20 ms | ILA 同步抓 `vsync` 与 `cmd_valid` 时间戳 |
| 手势命令 -> 画面变化 | <= 2 帧（约 33 ms） | 60 Hz tick + 显示双缓冲 |
| 端到端（含游戏逻辑） | <= 50 ms | 上述两项之和，现场用示波器/LED 打点验证 |
| 显示帧率 | 稳定 60 Hz | VGA 时序计数器 |
| 视觉处理帧率 | >= 25 fps | 帧有效信号计数器 |
| 时序收敛 | `WNS >= 0` @ 100 MHz | Vivado 实现报告 |
| 资源占用 | LUT <= 70%、BRAM <= 70%、DSP <= 60% | 综合实现报告 |

## 9. 变更流程

1. 修改本文件的**冻结项**需发起"接口变更提案"，说明动机、影响模块、回归测试范围。
2. 需要 **A + B + C 三方至少两方** 同意，且受影响方必须全员知晓。
3. 版本号 +0.1，更新文末变更记录，并同步 `docs/gesture_spec.md` 与 RTL。
4. **冻结期内禁止"先改代码后补文档"。**
