# 技能包（Skill Package）

> 本目录把开发过程中沉淀的可复用经验显式写出来，供**其他队伍直接套用**。
> 评价标准是可复用性：换题目、换板卡、换 EDA 版本后，这些条目是否仍然成立。
> 每条格式：**适用场景 → 现象/原理 → 做法 → 已验证效果 → 失效条件**。
>
> 本项目（摄像头光流手势控制的 FPGA 游戏）实际踩过的坑与提炼物如下。

---

## S1. 大位宽向量的变量下标会让综合卡死（RTL 设计）

**适用场景**：RTL 里对很宽的位向量（如掩体位图 `[1151:0]`、帧缓冲）做**变量下标**读写，
且在循环里遍历。

**现象**：综合能过，但实现阶段（Timing Optimization / 布局）长时间不结束、内存暴涨，
日志停在某一阶段不动。这不是"机器慢"，而是综合出了巨型 MUX。

**原理**：`bits[idx]` 中 `idx` 是变量时，综合器要为每个可能的 `idx` 建立选择通路；
1152 bit 的向量被 `for` 循环 + 变量下标访问，等价于 1152 选 1 的多路选择器堆叠，
面积与延迟都不可接受。

**做法**（三选一，按改动难度排序）：
1. **把变量下标改成固定坐标查表**：本项目最终用 `get_bunk_x(b)` 的 `case` 返回 4 个固定
   基地址（32/108/184/260），再配合常量偏移访问，彻底消掉动态寻址；
2. 用 **BRAM + 同步读**替代寄存器位图（存储换逻辑）；
3. 拆分访问粒度（按字节/按块寻址，而不是按 bit）。

**已验证效果**：改前实现阶段卡死；改后综合与实现一次通过，且 LUT 占用可预测。

**失效条件**：向量很窄（≤32 bit）时变量下标代价可接受，不必改。

## S2. XDC 里不能写行尾 `#` 注释（约束/构建）

**适用场景**：手写或"加注释"式整理的 XDC 引脚约束文件。

**现象**：综合正常，`write_bitstream` 阶段 DRC 报

```
ERROR: [DRC NSTD-1] Unspecified I/O Standard: 53 out of 53 logical ports use 'DEFAULT'
ERROR: [DRC UCIO-1] Unconstrained Logical Port: 53 out of 53 logical ports have no LOC
```

明明写了 `set_property PACKAGE_PIN`，却全部失效；日志里伴随：

```
CRITICAL WARNING: [Common 17-161] Invalid option value '#' specified for 'objects'
```

**原理**：XDC 是 Tcl。Tcl 只在**命令起始位置**识别 `#` 注释；
`set_property ... [get_ports x]   # 引脚说明` 里的注释会被当成 `set_property` 的
**额外参数**，于是整个 `set_property` 报错、约束丢失。

**做法**：
- 注释必须**单独成行**（行首 `#`），或放在命令**上一行**；
- 已有的行尾注释用脚本清理：对非注释行截断第一个 `#` 之后的内容；
- 清理后做**计数校验**（`set_property` 条数、`PACKAGE_PIN` 条数清理前后必须相等），
  避免误删命令。

**已验证效果**：本项目注释整理版清理 116 条命令 / 53 个引脚后，bitstream 由失败转为成功。

**失效条件**：无（Tcl 语义固定）。

## S3. 仿真加速：用参数覆盖缩短慢速节拍（验证）

**适用场景**：任何"分频产生慢速节拍"的设计（游戏机、秒表、呼吸灯、UART 采样）。

**现象**：`TICK_DIV = 833333`（50 MHz→60 Hz）时，跑 1 秒游戏要仿真 5000 万拍，
一次回归要几十分钟，调试无法迭代。

**做法**：把节拍分频做成 `parameter`，testbench 例化时覆盖：

```systemverilog
localparam int TICK_DIV = 833333;                 // 上板用默认值
game_core #(.TICK_DIV(10)) u_dut (...);           // 仿真用 10，逻辑完全一致
```

**已验证效果**：本项目 testbench 用 `TICK_DIV=10`，48.7 µs 仿真内跑完
"复位→开始→移动→开火→命中→掉命→UFO→暂停"全路径，14 条断言全通过。

**失效条件**：参数写成 `localparam` 或被硬编码时无法覆盖 → 写 RTL 时就把可调量放 `parameter`。

## S4. 用 Python 黄金模型验证硬件手势判决（算法验证）

**适用场景**：图像/信号处理类 RTL（肤色分割、光流、阈值判决），纯仿真波形难判断"对不对"。

**做法**：
1. 用 Python 实现同一套算法（本项目 `说明/scripts/gesture_golden_model.py`、
   `skin_calibrate.py`）；
2. 喂同一帧图像，比较 Python 与 RTL 的中间量（质心坐标、投票数、方向标签）；
3. 不一致时先查**量化/位宽**（定点 Q 格式、移位截断），再查时序对齐；
4. 把阈值参数做成寄存器/常量注释，标定一次写死，避免"换个教室就失效"。

**已验证效果**：本项目用该方法定位了标定阈值与定点截断误差，手势判决稳定后才上板。

**失效条件**：算法含强随机性或不可复现的浮点依赖时，需要先固定随机种子/定点化。

## S5. 手势/按键类输入的"去抖 + 迟滞 + 冷却"三件套（交互设计）

**适用场景**：任何"人手输入 → 数字命令"的设计（手势、按键、摇杆）。

**现象**：单帧判决直接驱动动作时，画面左右乱闪；按键一次触发多次。

**做法**：
1. **逐块/逐帧投票**：把空间上大量弱证据（300 个光流块的 u 符号）聚合成一帧一个结论；
2. **迟滞（漏桶）**：连续 N 帧同向才输出命令，静止时向 0 漏电回中立；
3. **冷却/去抖**：命令生效后强制保持 M 帧，屏蔽抖动；
4. 按键侧独立做 **2 级 FF 同步 + 计数消抖（5 ms）**，并明确"按住 ≥1 个游戏节拍"的要求。

**已验证效果**：本项目 `flow_fsm` 用"300 块投票 + 漏桶 ±8（阈值 3）"后，挥手操作稳定、
停手能归零，答辩现场演示无乱跳。

**失效条件**：输入速率极高（>100 Hz）时，投票窗口要相应缩短。

## S6. Vivado 一键构建 + 报告导出模板（工程化）

**适用场景**：需要提交"可复现构建脚本"的课程/竞赛；多人协作避免"只在我电脑上能跑"。

**做法**：见 [`build/build.tcl`](../build/build.tcl)，要点：
1. `create_project -force` + `add_files`（含子目录）+ `set_property top`；
2. **自动生成时钟 IP**（`create_ip clk_wiz` + `generate_target`），IP 不入库也能重建；
3. `launch_runs synth_1` → `wait_on_run` → 检查 `PROGRESS == 100%` → `open_run` → `report_*`；
4. 用 `get_timing_paths` + `get_cells -filter {REF_NAME =~ LUT*}` 把关键指标写进
   `00_metrics.txt`，报告数字直接抄；
5. 报告输出到 `build/report/`，与 `build/cam_game/`（工程产物，gitignore）分离。

**已验证效果**：本项目一条命令产出 bitstream（3.65 MB）+ 11 份报告，评委可原样复现。

**失效条件**：器件型号/顶层名不匹配会报 `top not found`；无 XDC 时实现阶段报
unconstrained IO（脚本已做存在性检查）。

## S7. EDA 工具禁用含中文的路径（环境）

**适用场景**：Windows 中文用户名（如 `C:\Users\张三\Desktop`）下用 Vivado / ModelSim。

**现象**：

```
init_dbinfo() DATABASE ERROR: (sqlite3_open C:/Users/<乱码>/.../work/_lib.qdb): unable to open database file
** Fatal: (vlog-9) Problem while writing token file ".../work/_temp/..."
** Error: can't read "FileWatch(fileName)": no such element in array
```

**原理**：部分组件是 ANSI 构建，非 ASCII 路径被错误编码，数据库/临时文件创建失败；
报错往往指向别处（如 "Error loading design"），非常难查。

**做法**：工程、工作目录、`TMP`/`TEMP` 全部用纯英文（如 `D:\fpga\work`）；
若必须在中文用户名下工作，先把 `TMP`/`TEMP` 指向英文目录再启动工具。

**已验证效果**：同一套源码在中文路径下 vlog 直接失败；换到 `C:\msim_game` 后 0 error。

**失效条件**：Linux/macOS（UTF-8 路径无此问题）。

## S8. 答辩三问的固定回答框架（文档/答辩）

**适用场景**：评审必问"几个状态机？怎么设计？几个时钟域？如何协调？"

**做法**：三段式
1. **数量与分工**：主控 FSM（几个状态、编码）+ 辅助时序控制器（计时器/序列）+ 板级配置状态机（SCCB/DDC）；
2. **编码与迁移**：状态表 + 迁移条件表 + 在哪个使能沿采样 + 优先级顺序 + Moore/Mealy；
3. **时钟域**：几个时钟、各自来源与频率、哪些是真异步（→2FF 同步器/双口 RAM/false_path）、
   哪些是同源分频（→STA 直接分析）、跨域用什么机制保证一致性（快照/握手）。

**已验证效果**：本项目按此结构写成 `docs/architecture.md` 第 3、4 节，全部有 RTL 依据可查。

**失效条件**：无。
