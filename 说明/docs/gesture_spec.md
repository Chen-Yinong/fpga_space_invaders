## 1. 输入特征（PL 每帧计算一次）

视觉流水线在**每帧结束**（`vsync` 后沿）产生一组稳定特征，跨到 `clk_100m` 域后供手势状态机使用。
特征含义、位宽与取值范围如下（按采集分辨率 **640×480** 表述）：

| 特征 | 符号 | 位宽 | 范围 | 说明 |
| --- | --- | --- | --- | --- |
| 手部质心 X | `feat_cx` | 10 bit | 0 .. 639 | 前景掩膜的水平质心 |
| 手部质心 Y | `feat_cy` | 9 bit | 0 .. 479 | 竖直质心，默认不参与判定，仅用于日志 |
| 前景像素数 | `feat_area` | 20 bit | 0 .. 307200 | 二值掩膜前景像素总数 |
| 包围盒宽 | `feat_w` | 10 bit | 0 .. 640 | 前景最小外接矩形宽度 |
| 包围盒高 | `feat_h` | 9 bit | 0 .. 480 | 前景最小外接矩形高度 |
| 张开度 | `feat_open` | 10 bit | 0 .. 1000 | `1000 * area / (w * h)`；手掌张开偏大，握拳偏小 |
| 质心水平速度 | `feat_vx` | 12 bit 有符号 | -320 .. +320 | 当前帧与上一帧 `cx` 之差，单位 像素/帧 |

**归一化与缩放约定**

- 上文阈值均以 640×480 采集分辨率表述。
- 若为节省资源把视觉处理降到 320×240，则换算关系为：
  `cx/w → ×1/2`、`cy/h → ×1/2`、`area → ×1/4`、`open` 不变（无量纲）。
- **所有阈值必须来自 AXI4-Lite 寄存器，禁止在 RTL 中硬编码**，以便现场标定与回放调试。

## 2. 四种手势总览

四种手势覆盖游戏的全部操作，手势语义与游戏动作严格一一对应：

| 编号 | 名称 | 游戏动作 | 主要判别特征 | 触发方式 |
| --- | --- | --- | --- | --- |
| **G1** | 左移（Move Left） | 战机向左移动 | 质心进入左区 + 手掌张开 | **电平保持** |
| **G2** | 右移（Move Right） | 战机向右移动 | 质心进入右区 + 手掌张开 | **电平保持** |
| **G3** | 射击（Fire） | 发射子弹 | 张开度由高到低的**边沿** | **单次脉冲** |
| **G4** | 开始 / 重开（Start） | 开始或重新开始一局 | 左右往返挥动计数 | **单次脉冲** |

设计原则：

1. **移动用空间位置，不靠挥手** —— 位置信号天然稳定、易去抖、单手即可持续控制。
2. **射击用开合边沿，不用位置** —— 与移动完全正交，可边移动边射击。
3. **开始用重复性动作** —— 需要"故意的、不易误触发的"手势，避免玩家手停在画面中间就开局。

### 2.1 画面分区（冻结）

以采集分辨率 640×480 为例，水平方向划分三个区域：

```
 cx:    0                        192        384            448          639
        |-------------------------|-----------|--------------|-----------|
        |        左区 LEFT        |  中区 MID  |   右区 RIGHT  |  右侧边缘  |
        |   G1 进入(<=191)         |  无移动   |  G2 进入(>=449)|          |
        |   G1 退出(>=256)         |            |  G2 退出(<=384)|          |
```

- **进入阈值与退出阈值不同（迟滞 / hysteresis）**，避免手停在分界线附近时抖动。
- 分区边界必须是 AXI4-Lite 可配置寄存器：`REG_LEFT_ENTER`、`REG_LEFT_EXIT`、
  `REG_RIGHT_ENTER`、`REG_RIGHT_EXIT`。
- 默认值：`LEFT_ENTER=192(0.30W)`、`LEFT_EXIT=256(0.40W)`、
  `RIGHT_ENTER=448(0.70W)`、`RIGHT_EXIT=384(0.60W)`。

### 2.2 张开度判据（冻结）

| 参数 | 寄存器 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 张开判据 | `REG_OPEN_TH` | 480 | `feat_open >= 480` 视为"手掌张开" |
| 握拳判据 | `REG_CLOSE_TH` | 300 | `feat_open <= 300` 视为"握拳" |
| 有效面积下限 | `REG_AREA_MIN` | 2000 | 小于此值判为噪声/无手 |
| 有效面积上限 | `REG_AREA_MAX` | 120000 | 大于此值判为背景/人体误入 |

当 `feat_area < REG_AREA_MIN` 或 `feat_area > REG_AREA_MAX` 时，本帧视为 **无效帧**：
不产生任何新手势、不更新迟滞状态，但**已锁存的移动命令保持**（避免手短暂丢失导致战机停止）。

## 3. 逐手势详细定义

### G1 左移（Move Left）

| 项目 | 定义 |
| --- | --- |
| 语义 | 战机持续向左移动，直到手离开左区 |
| 前置条件 | `feat_area` 在 `[AREA_MIN, AREA_MAX]` 内 且 `feat_open >= OPEN_TH` |
| 进入条件 | `feat_cx <= LEFT_ENTER (192)` 连续 **N_ON = 5** 帧 |
| 退出条件 | `feat_cx >= LEFT_EXIT (256)` 连续 **N_OFF = 3** 帧 |
| 输出 | `cmd_valid=1, cmd=4'b0001`，**持续有效**（电平） |
| 冷却 | 无（移动是连续控制量） |
| 移动步长 | 由 `game_core` 决定：`PLAYER_SPEED` 像素/帧，默认 2 像素/帧 @60 Hz |
| 误触发防护 | 必须同时满足张开判据，避免"手放下掠过左下角"被误判 |

### G2 右移（Move Right）

| 项目 | 定义 |
| --- | --- |
| 语义 | 战机持续向右移动 |
| 前置条件 | 同 G1 |
| 进入条件 | `feat_cx >= RIGHT_ENTER (448)` 连续 **N_ON = 5** 帧 |
| 退出条件 | `feat_cx <= RIGHT_EXIT (384)` 连续 **N_OFF = 3** 帧 |
| 输出 | `cmd_valid=1, cmd=4'b0010`，**持续有效**（电平） |
| 冷却 | 无 |
| 互斥 | G1 与 G2 在状态机中互斥；同时满足时以**最近一次稳定状态**为准，绝不输出 `0011` |

### G3 射击（Fire）

| 项目 | 定义 |
| --- | --- |
| 语义 | 发射一颗子弹（若弹药/冷却允许） |
| 前置条件 | `feat_area` 在 `[AREA_MIN, AREA_MAX]` 内 |
| 进入条件 | 上一稳定态为"张开"（`open >= OPEN_TH`），且当前帧 `open <= CLOSE_TH`（**下降沿**），连续 **N_FIRE = 2** 帧确认 |
| 输出 | `cmd_valid=1, cmd=4'b0100`，**单周期脉冲**（1 帧内 1 拍） |
| 冷却 | **T_FIRE_COOL = 300 ms**（约 9 帧 @30 fps）；冷却期内新的下降沿被忽略 |
| 误触发防护 | (a) 必须有前置的"张开"状态，避免手从画面外伸入直接触发；<br>(b) `area` 必须在合法范围内，握拳后 `area` 会明显小于张开，需核对 `AREA_MIN`。<br>(c) 冷却时间可配 `REG_FIRE_COOL_MS`。 |
| 备注 | 握拳后手掌 `area` 会下降约 30%–50%，若标定时发现 `CLOSE_TH` 处 `open` 不收敛，可改用 **`open` 的一阶差分** `d_open <= -D_OPEN_TH` 作为备用判据（寄存器 `REG_FIRE_MODE`，0=阈值，1=差分）。 |

### G4 开始 / 重开（Start / Restart）

| 项目 | 定义 |
| --- | --- |
| 语义 | 在 IDLE / GAME_OVER 状态开始新一局；游戏中按下则回到 IDLE（暂停语义由 C 决定） |
| 前置条件 | `feat_area` 在 `[AREA_MIN, AREA_MAX]` 内 且 `feat_open >= OPEN_TH` |
| 进入条件 | 在 **T_WAVE_WIN = 1500 ms** 窗口内，`feat_vx` 的**符号变化次数 >= 4**（即完成约 2 次左右往返），且每次往返幅度 `|Δcx| >= 96` 像素 |
| 输出 | `cmd_valid=1, cmd=4'b1000`，**单周期脉冲** |
| 冷却 | **T_START_COOL = 2000 ms**，防止一次挥手重复开局 |
| 备用方案 | 若挥手在现场光照下不稳定，可切换为"张开手掌停留在中区（384<=cx<=... 实际 256<=cx<=384）连续 60 帧（约 2 s）"，由 `REG_START_MODE` 选择：0=挥手（默认），1=中区停留 |
| 误触发防护 | 挥手判据本身要求**往复**而非单向移动，因此与 G1/G2 的"单向进入分区"不会冲突；但在挥手期间**抑制** G1/G2 输出 |

## 4. 对外命令接口（冻结）

手势状态机的唯一输出为一条命令总线：

```verilog
output             cmd_valid;   // 命令有效，高电平有效
output       [3:0] cmd;         // 独热编码（one-hot）
```

| `cmd[3]` | `cmd[2]` | `cmd[1]` | `cmd[0]` | 名称 | 有效方式 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 0 | 1 | `CMD_MOVE_LEFT` | 电平保持 |
| 0 | 0 | 1 | 0 | `CMD_MOVE_RIGHT` | 电平保持 |
| 0 | 1 | 0 | 0 | `CMD_FIRE` | 单拍脉冲 |
| 1 | 0 | 0 | 0 | `CMD_START` | 单拍脉冲 |
| 0 | 0 | 0 | 0 | `CMD_NONE` | 无命令（`cmd_valid=0`） |

采用**独热编码**的原因：跨时钟域后多比特信号同时翻转容易产生虚假中间码字，
独热编码下任何单比特毛刺只会变成"未定义但安全"的组合，且便于 ILA 抓取与调试。

**跨时钟域约定**：`cmd_valid`/`cmd` 从视觉域（`clk_pix`）跨到游戏域（`clk_100m`）时，
必须经**握手或双触发器同步 + `valid` 脉冲展宽**，不得直接采样多比特电平。详见 `docs/interface_spec.md` 第 5 节。

## 6. 手势状态机（参考实现，B 负责）

```
        +--------+
        |  IDLE  |<-----------------------------------+
        +--------+                                    |
             | 连续 N_ON 帧满足进入条件                 | START 冷却结束
             v                                         |
   +--------------------+   cx>=LEFT_EXIT ×N_OFF   +---------+
   |   MOVE_LEFT(保持)  |------------------------->|  IDLE   |
   +--------------------+                          +---------+
             ^                                         |
             | 连续 N_ON 帧满足进入条件                 |
   +--------------------+                              |
   |  MOVE_RIGHT(保持)  |------------------------------+
   +--------------------+   cx<=RIGHT_EXIT ×N_OFF

   任意状态（除 START 冷却期）:
     检测到 open 下降沿 ×N_FIRE  -> 发 CMD_FIRE 脉冲 -> 回到当前状态
     检测到挥手计数达标        -> 发 CMD_START 脉冲 -> 进入 START 冷却
```

**状态机硬性要求**

1. 每个状态的进入/退出都必须有帧计数器，禁止"单帧即切换"。
2. `CMD_FIRE` 与 `CMD_START` 必须是**单拍脉冲**，由 `game_core` 侧持有或本模块脉冲展宽保证不丢失。
3. 复位后必须回到 IDLE，且前 **10 帧**为"热身期"（丢弃），等待流水线填满。

## 7. 标定与数据采集

为保证 7.x 节验收标准可复现，团队需要采集一份小型手势数据集：

- 存放位置：`data/gesture/`，子目录 `left/`、`right/`、`fire/`、`start/`、`idle/`。
- 采集条件：**三种光照**（室内日光灯、台灯侧光、背光）× **两种背景**（纯色墙面、杂物桌面）× **两到三名成员**。
- 每组手势至少 30 段，每段 3–5 s，命名 `g1_left_light01_bg02_p01_seq03.mp4`。
- **仓库只提交小尺寸样本**（降采样到 320×240、每类 2–3 段，单文件 < 5 MB），
  完整数据集放本地或使用 Git LFS，禁止把原始大视频直接 push。
- Python golden model 必须能读同一目录并自动跑出混淆矩阵（见 `docs/repo_conventions.md` 第 6 节）。

## 8. 验收标准（第零阶段冻结，后续沿用）

| 编号 | 验收项 | 判据 |
| --- | --- | --- |
| A1 | 四种手势全部可识别 | 30 次有效手势测试，每种手势成功率 **>= 90%** |
| A2 | 误触发率 | 空闲 1 分钟（有人在画面内做非手势动作），误触发 **<= 1 次** |
| A3 | 端到端延迟 | 手势发生 -> 游戏中可见响应 **<= 20 ms**（不含摄像头曝光） |
| A4 | 可复现 | 换同型号板卡 + 本仓库脚本可重建并达到 A1–A3 |
| A5 | 参数可调 | 第 5 节所有参数均可通过 AXI4-Lite 在线读写，掉电默认值见本文件 |

## 9. 变更流程

1. 任何阈值、分区、编码改动，先在本文件开一个"变更提案"小节，写清原因、影响模块、回滚方式。
2. 至少 **两个角色**（B 必签 + A 或 C 之一）确认后，把版本号 +0.1 并更新文末"变更记录"。
3. 同步刷新 `docs/interface_spec.md` 的寄存器表与 `sim/` 中的测试向量。
4. **禁止只在代码里改阈值而不改本文件。**
