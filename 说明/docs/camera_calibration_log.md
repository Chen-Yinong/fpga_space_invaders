# 摄像头肤色标定与背景差分实测记录

> 记录方式：按住 `key1` 时，屏幕左上角直接显示本帧采到的 `Cb` / `Cr` 均值（`num_overlay`）。
> 上面的数字是 `Cb`，下面是 `Cr`。这是**板上实测值**，不是估算。

---

## 1. 2026-10-17 首次实测（升腾Pro + OV7725，室内暖光）

| 采样对象 | 条件 | Cb | Cr | Cr−Cb | 彩度 \|Cb−128\|+\|Cr−128\| |
| --- | --- | --- | --- | --- | --- |
| **手** | 手放在中央 80×80 标定框内，保持不动 1–2 s | **110** | **158** | **+48** | **48** |
| **背景** | 手完全移开，框内只有背景 | **127** | **125** | **−2** | **4** |

**结论**：本场景下肤色与中性背景在颜色上**可分离**。

- `Cr − Cb`：手 `+48` vs 背景 `−2`，相差 50；
- 彩度：手 `48` vs 背景 `4` —— 背景是中性色，不属于肤色区。

---

## 2. 肤色判据（`top_cam_game.sv`）

三条同时满足才算肤色：

```systemverilog
skin = (Cb ∈ [cb_lo, cb_hi])          // 标定得到的区间
    && (Cr ∈ [cr_lo, cr_hi])
    && (|Cb−128| + |Cr−128| >= 16)    // 够彩：挡灰/白/浅色
    && (Cr − Cb >= 30)                // 够暖：本场景关键判据（手 +48，暖白墙约 +20）
```

标定结果（`MARGIN = 8`）为 `Cb[102,118] × Cr[150,166]`；上电默认
`Cb[95,125] × Cr[145,180]`（按上面实测的手值收紧）。

---

## 3. 为什么必须加背景差分（2026-10-17 晚）

加入 `Cr − Cb ≥ 30` 之后，**暖白墙被排除了，但木桌开始变绿** —— 木头的 `Cb/Cr`
和手几乎一样（`Cr−Cb ≈ 47`），**颜色判据在原理上无法区分**。同时手内部出现
闪烁的空洞（手内部亮度不均，部分像素在阈值边界进出）。

结论：**纯颜色到头了，必须引入"静止 vs 运动"这一维。**

### 3.1 为什么不用最大连通域

`说明/script2/../scripts/square_demo.py` 用 `cv2.findContours` 取最大连通域，
能忽略背景里的肤色块。但本项目不适用：

1. **本场景里最大的肤色块是木桌，不是手**（桌板约 8 万像素，手约 1 万像素），
   取最大连通域会直接锁到桌板上；
2. **延迟超标**：两遍扫描要求整帧标签留在片内，延迟升到 1~2 帧（33~66 ms），
   违反 `interface_spec.md` 里"命令→画面 ≤ 33 ms"的冻结预算；
3. **验证困难**：等价表（union-find）是随机访问的指针链，破坏每拍一像素的流水线；
   bug 表现为"偶尔选错连通域"，仿真难复现。

### 3.2 采用的方案：背景差分（`cam_frame_buf.sv`）

```
Y    = (77R + 150G + 29B) >> 8       亮度
fg   = |Y − bg| > 16                 和背景差得远 = 有东西挡在前面
hand = skin & fg                     既像肤色、又不是静止背景
```

四条保护机制：

| 机制 | 参数 | 作用 |
| --- | --- | --- |
| 上电初始化 | `INIT_FRAMES = 40`（约 1.3 s） | 把墙、桌等静止物**无条件**学成背景，与颜色无关 |
| 慢速跟随 + 只学非肤色 | `bg += (Y−bg)>>6`，仅当 `!skin && |Y−bg|<16` | 换场地约 2 秒自适应；**手是肤色，永远学不进背景**（停住也不会被吸收） |
| 场景切换重建 | 一帧前景 > 60% → 强制重建 4 帧 | 挪摄像头/开关灯后 1~2 帧恢复 |
| 标定期冻结 | `freeze_bg = calib_busy` | 防止框里的手被背景吸收 |

资源代价：背景缓存 320×240×8bit = 17 个 BRAM36（实测 BRAM 54 → **78 / 135**），
LUT 5019 → **5680**，延迟只增加 1 拍。

### 3.3 已知边界

- **和背景"同色又同亮度"的物体分不开** —— 亮度差为 0 时 `fg = 0`，物理上无解。
  仿真里把木桌设成和手**完全相同**的 RGB565 时确实检测不到；改成"同色系但更暗"
  （现实中皮肤总比木头亮）即可正常分离。
- **身后有人走动**：他们是前景，露出的皮肤会被统计进去。演示时应保证背景无人。
- **手完全静止超过 2 秒**会被缓慢吸收 —— 但此时本来就不应有移动指令，
  与 `gesture_spec.md` 的"手停 = 不动"一致。

### 3.4 仿真验证（`fpga_space_invaders/sim/tb_skin_contour.sv`）

场景：上半屏暖白墙 + 下半屏木桌（同色系但更暗，`Cr−Cb=47`，颜色判据必然误判）+ 移动的手。

```
TB   静止木桌未被误判 OK（与手同色也不描边）
TB   移动的手有白轮廓（命中 3 个像素）
TB   暖白墙未被误判 OK (efe7d6)
TB   标定: cb[94,110] cr[147,163] stat=3 上屏 Cb=102 Cr=155
===== ALL PASS =====
```

帧缓存输出见 `fpga_space_invaders/sim/contour_320x240.png`：墙与桌均无轮廓，
只有移动的手被完整勾出。

## 4. 遗留

- 实测为**单点、单次、单光照**，仅能证明本场景可分离，不能替代不同光照下的复测。
- 换环境/换光照后建议重新标定并记录新的 `Cb/Cr`（框变绿即为标定可用）。
- 若出现"手与环境 `Cr−Cb` 差值 < 20"的场地，需进一步依赖背景差分，而不是调阈值。
