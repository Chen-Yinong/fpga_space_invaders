## 1. 选题背景与创新点

### 1.1 为什么做这个题目

经典街机《太空侵略者》规则清晰、状态机完整、对实时性要求高，是检验"能不能用纯硬件
把一套完整交互系统跑起来"的好载体。但我们不满足于复刻：

- 传统 FPGA 游戏作业的输入是 4 个按键，交互维度低、演示效果平淡；
- 摄像头 + 计算机视觉在 FPGA 上通常只做到"图像显示"，很少真正用视觉**驱动实时交互**；
- 视觉算法在软件里容易写，在 FPGA 上要在**资源、时序、跨时钟域**三重约束下重写。

**因此本题的核心问题不是"怎么画游戏"，而是"如何在 25 MHz 像素流上，用纯 RTL 实时
解算光流，并把噪声很大的视觉证据变成稳定的人机命令"。**

### 1.2 前人工作与差异

| 参考方向 | 常见做法 | 我们的差异 |
|---|---|---|
| 开源 FPGA 版太空侵略者（GitHub 多个实现） | 按键输入、VGA 输出、固定敌阵 | 手势输入 + HDMI + 光流矢量可视化 |
| FPGA 光流实现（Lucas-Kanade / Horn-Schunck） | 追求单点精度，常需外部 DDR 存帧；多为演示级 | 全片内乒乓双缓冲，300 块并行、流水化定点除法，直接服务于**控制**而非测量 |
| 手势识别（软件/嵌入式） | 神经网络或肤色分割，跑在 CPU/GPU 上 | 纯 RTL 无 CPU、无外部存储依赖，端到端延迟可控 |

### 1.3 创新点（四条）

1. **全硬件 LK 光流**：`lk_flow` 在 24 MHz 摄像头时钟域内，对 20×15=300 个 16×16 块
   并行解算 `u/v`（Q16 定点），自研 70 拍恢复余数法除法器 `div_pipe` 完成两次除法。
2. **投票 + 漏桶的鲁棒判决**：单块光流不可信，`flow_fsm` 用"逐块投票 → 每帧方向判定 →
   漏桶积分（±8，阈值 3）"三级顺序决策，把 300 个弱证据聚合成稳定命令，静止自动回中立。
3. **可解释的画中画**：右上角 160×120 区域实时渲染光流矢量场（红=左 / 绿=右 / 灰=静止），
   评委与调试者能**直接看到算法在做什么**——这是"黑盒识别"做不到的。
4. **三时钟域 + 三种跨域机制的工程化组合**：摄像头域（异步）→ 系统域用 2FF 同步器、
   → 显示域用双口 RAM；系统域→显示域（同源 MMCM）用 toggle 信箱快照防撕裂。

## 2. 设计原理与功能框图

### 2.1 系统框图

### 2.2 关键算法：分块 Lucas-Kanade

对每个 16×16 块，取 2×2 抽样点，累加

```
A = Σ Ix²,  B = Σ IxIy,  C = Σ Iy²,  D = Σ IxIt,  E = Σ IyIt
```

解 2×2 方程得块运动矢量，再按符号投票决定整帧方向。屏内 20×15 块共 300 个，
每块独立解算，天然并行——这是 FPGA 相对 CPU 的结构性优势。

### 2.3 游戏本体

规则完整实现经典街机：55 只外星人（11×5）、4 座可逐位破坏的掩体、6 发并行子弹、
随机神秘飞碟（50/100/150/300 分）、3 关递进（每关下移一格、加速、最后一关上调射速）、
经典街机分色（顶行浅蓝/中间白色/底部黄色、掩体绿色、飞碟红色）、胜负结算与通关画面。

## 3. 软硬件划分依据与接口设计

| 决策 | 选择 | 依据 |
|---|---|---|
| 光流放哪个时钟域 | 摄像头 `cam1_pclk` 域（24 MHz） | 与像素流同源，避免先跨域再算；该域负载独立于游戏逻辑 |
| 游戏核心放哪个域 | `sys_clk` 50 MHz | 60 Hz 节拍需要稳定的低频使能；与按键消抖同域，无跨域负担 |
| 显示放哪个域 | MMCM 分频的 `clk_25m` | 满足 640×480@60 的像素时钟；与系统域同源，时序可分析 |
| 是否用 CPU/PS | 不用，纯 RTL | 作品定位为纯硬件交互演示；省去软硬件协同复杂度，延迟更低 |
| 帧缓冲放哪 | 片内 BRAM（48×RAMB36） | 150 KB 双缓冲刚好放下；避免 DDR 访问的不确定延迟 |

**关键接口**（完整寄存器/信号定义见 `说明/docs/interface_spec.md`）：

| 接口 | 位宽 | 说明 |
|---|---|---|
| `cam1_data[7:0]` + `pclk/href/vsync` | 11 | OV7725 DVP，RGB565 两拍拼一个像素 |
| `sccb1_scl/sda`、`ddc_scl/sda` | 2×2 | SCCB 配置摄像头、DDC(I2C) 配置 HDMI 发送芯片 |
| 手势跨域 | 2 bit | `gest_left/right`（2FF 同步 + 镜像反转） |
| 游戏状态快照 | ~2 kbit | 坐标/位图/分数/生命/关卡，toggle 握手整包复制 |
| HDMI 输出 | 24+5 | RGB888 + clk/hs/vs/de/rst |

## 4. 优化过程（含前后对比）

| 版本 | 改动 | 结果 | 依据 |
|---|---|---|---|
| V1.0 | 基线：完整光流 + 游戏 + HDMI | 功能跑通 | — |
| V1.1 | 掩体位图变量下标改 `get_bunk_x` case 固定坐标 | 实现阶段由"卡死"变"通过" | 1152 bit 向量变量下标综合出巨型 MUX（见 `skill/README.md` S1） |
| V1.2 | XDC 行尾注释清理 | bitstream 由失败变成功 | Tcl 不支持行尾注释，53 个引脚约束曾全部失效（S2） |
| V1.3 | 仿真加速：`TICK_DIV` 参数覆盖 | 回归时间从数十分钟降到秒级 | 见 `sim/tb_game_core.sv`（S3） |
| V2.0（待做） | `lk_flow` 的 6 个 Σ 累加 FIFO 改同步复位，争取映射 BRAM | 预计 FF 下降 | 综合日志 `Synth 8-4767`：带异步复位的 RAM 无法用 BRAM |

**资源与时序实测**（Vivado 2026.1，完整报告见 `docs/synthesis_report.md`）：

| 指标 | 数值 |
|---|---|
| LUT / FF | 16,265（25.65%）/ 6,800（5.36%） |
| BRAM / DSP | 48.5（35.93%）/ 12（5.00%） |
| 时序 | WNS **+3.428 ns**、WHS +0.090 ns（14,175 端点，0 失败） |
| 功耗 | 0.282 W（动态 0.182 + 静态 0.100） |
| 三时钟 | 24 MHz（摄像）/ 50 MHz（系统）/ 25 MHz（显示） |

**分析**：BRAM 占用最高（35.9%），几乎全被灰度帧双缓冲吃掉（320×240×8bit×2 帧）；
LUT 仅 25.6%，说明瓶颈在**片内存储**而非逻辑——这是"为什么暂不做 720p"的直接依据。

## 7. 复现说明

### 7.1 环境

- Vivado 2026.1（2025.2 亦可，需在报告中注明）
- 野火升腾Pro XC7A100T-FGG484-2 + OV7725 模组 + HDMI 显示器
- 无需安装额外 IP：`hdmi_pll` 由脚本自动生成

### 7.2 一条命令构建

```bash
git clone https://github.com/Chen-Yinong/fpga_space_invaders.git
cd fpga_space_invaders
vivado -mode batch -source build/build.tcl
# 产出：build/report/*.rpt、build/cam_game/.../impl_1/top_cam_game.bit
```

### 7.3 仿真

```bash
# Vivado GUI：Add Sources → sim/tb_game_core.sv → Run Behavioral Simulation → run -all
# 预期：14 条断言全部 PASS（见 sim/sim_log.txt）
```

### 7.4 上板

1. 烧写 `board/top_cam_game.bit`（Hardware Manager → Program Device）
2. 摄像头朝向操作者，保证光照充足、背景有纹理（光流需要纹理）
3. 上电后：HDMI 显示待机画面，右上角画中画显示光流矢量场
4. 操作：**挥手左右**控制炮台；**key2** 开始/暂停/继续；**key3** 重开
5. 验收要点：挥手时画中画对应区域变红/绿；停手变灰

### 7.5 复现一致性核对清单

| 检查点 | 期望 |
|---|---|
| 器件/顶层 | `xc7a100tfgg484-2` / `top_cam_game` |
| 资源 | LUT 16,265 ±2%、BRAM 48.5、DSP 12 |
| 时序 | WNS > 0、无 unconstrained path |
| 仿真 | 14 条断言全过 |
| 上板 | 挥手可控制、画中画随动作变色、三关可通 |

## 附：已知不足与后续工作

1. **hold 余量仅 +0.090 ns**：属"刚好满足"，若换更快的像素时钟需重新收敛；
2. **`lk_flow` 的 6 个累加 FIFO 未映射到 BRAM**（异步复位所致），FF 偏多；
3. **光流对光照敏感**：强背光或纯色背景时能量不足，画中画会全灰——已在文档中说明
   使用条件，后续可加自动曝光/AWB 控制；
4. **未做音频**：PWM 音效模块设计已完成但未接入（不影响主功能）。
